# 시작하기

공공임대주택(건설임대) 단지·주택형 카탈로그와 입주자 모집공고를 공공데이터포털 API 5개에서 모아
H2 파일 DB에 쌓는다. 처음 받는 사람이 인증키를 발급받고 적재를 돌려 보는 데까지 필요한 것만 적는다.

원천을 왜 그렇게 골랐고 무엇이 안 이어지는지는 [원천-정리.md](원천-정리.md), 필드 사전은
[원천-API-데이터-사전.md](원천-API-데이터-사전.md), 모델은 [도메인-설계.md](도메인-설계.md)에 있다.

## 1. 인증키 — 각자 발급받는다

**남의 키를 받아 쓰지 않는다.** 이유가 셋이다.

- **일일 한도를 나눠 쓰게 된다.** data.go.kr 한도는 계정·서비스 단위다(개발계정 10,000회/일).
  2026-08-16에 두 사람이 같은 키로 각각 `/complexes`를 돌려 마이홈 한도를 함께 소진한 적이 있다.
  전국 적재 한 번이 시군구 256개 × 페이지라 금방 찬다.
- 활용신청이 신청자 계정에 묶인다.
- 키가 새면 그 계정의 모든 서비스가 같이 샌다.

[data.go.kr](https://www.data.go.kr) 로그인 후 아래 5개를 **각각 활용신청**한다. 전부 개발계정 자동승인이라
바로 쓸 수 있다.

| 데이터 ID | 이름 | 쓰는 곳 |
| --- | --- | --- |
| [15110581](https://www.data.go.kr/data/15110581/openapi.do) | 마이홈 공공임대주택 단지정보 | 단지·주택형 카탈로그 생성 |
| [15108420](https://www.data.go.kr/data/15108420/openapi.do) | 마이홈 공공주택 입주자 모집공고 | 공고와 단지 단위 공급행 생성 |
| [15057999](https://www.data.go.kr/data/15057999/openapi.do) | LH 분양임대공고별 상세정보 | 일정·접수처·첨부 |
| [15056765](https://www.data.go.kr/data/15056765/openapi.do) | LH 분양임대공고별 공급정보 | 공급행을 주택형 단위로 재구성 |
| [15059475](https://www.data.go.kr/data/15059475/openapi.do) | LH 임대주택 단지별 조건 | 주택형 전체 세대수·기준 임대조건 |

승인되면 마이페이지에서 **일반 인증키**를 복사한다. 5개가 같은 키를 쓰고, Encoding·Decoding 값 아무거나 된다.

### 키를 넣는 법

레포에는 넣지 않는다. 환경변수로만 읽는다.

```properties
# application.properties — 이미 이렇게 되어 있다
domain.ingest.service-key=${DATA_GO_KR_SERVICE_KEY:}
```

```bash
DATA_GO_KR_SERVICE_KEY='발급받은키' ./gradlew bootRun
```

셸 프로필(`~/.zshrc`)에 `export DATA_GO_KR_SERVICE_KEY='…'` 로 두거나, IntelliJ 라면
Run/Debug Configurations → Environment variables 에 넣어도 된다.

`.env` 파일을 쓴다면 `.gitignore` 에 먼저 추가한다 — 지금은 등록돼 있지 않다.

**키 없이 앱을 띄우면** 모든 적재가 0초 만에 `failed` 로 끝난다. 네트워크를 타기 전에 예외가 나서
한도 초과와 헷갈리기 쉽다. `scripts/ingest.sh` 가 시작할 때 이걸 먼저 가려 준다.

## 2. 실행

```bash
DATA_GO_KR_SERVICE_KEY='발급받은키' ./gradlew bootRun
```

`80% EXECUTING` 에서 멈춘 것처럼 보이는 게 정상이다. `bootRun` 은 앱이 사는 동안 안 끝나는 태스크다.
로그에 `Started DomainApplication` 이 찍혔으면 뜬 것이고, 내리려면 Ctrl+C 를 누른다.

## 3. 적재

```bash
./scripts/ingest.sh                       # 다섯 단계 전부
./scripts/ingest.sh notices lh-notices    # 일부만
./scripts/ingest.sh links                 # 매칭 규칙만 고쳤을 때 (원천 재호출 없음)
```

**순서가 있다.** 공급행이 카탈로그를 가리키려면 단지가 먼저 있어야 하고, 주택형까지 쪼개려면
LH 원천이 먼저 와야 한다.

| 단계 | 원천 | 걸리는 시간 |
| --- | --- | --- |
| `/complexes` | 15110581 | **약 17분** (시군구 256개) |
| `/lease-infos` | 15059475 | 25초 |
| `/notices` | 15108420 | 4초 |
| `/lh-notices` | 15057999 + 15056765 | 2~3분 |
| `/links` | 없음 | 1초 미만 |

`/complexes` 를 하루에 여러 번 돌리지 않는다. 한 번이 한도의 상당 부분을 쓴다. 카탈로그는 느리게
변하니 보통은 뒤의 네 단계만 돌리면 된다.

### 실패했을 때

`failed` 가 0이 아니면 셋 중 하나다.

```
인증키 누락        앱을 키 없이 띄웠다. 0초 만에 끝나면 대개 이것이다
일일 한도 초과      429 / LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR (코드 22)
                 자정(KST)에 리셋된다
게이트웨이 오류      SERVICETIMEOUT_ERROR 나 빈 응답. LH 쪽이 간헐적으로 불안정하다
                 다시 돌리면 대개 된다
```

`/complexes` 는 한도에 걸려도 HTTP 200 에 `{"failed":256}` 으로 온다. 스크립트가 실패 100건을 넘으면
멈춘다 — 계속 두들겨도 소용없다.

**중간에 끊겨도 앞 단계 결과는 DB 에 남는다.** 적재는 upsert 라 다시 돌리면 이어진다. 다만
**삭제는 하지 않는다** — 제외 규칙을 새로 넣어도 이미 들어온 행은 안 빠지므로 SQL 로 지워야 한다.

## 4. DB 보기

파일 DB 하나에 테이블 7개다. 경로는 `data/domain-construction-rental-v4` 이고 `data/` 는 gitignore 다.

```
JDBC URL   jdbc:h2:file:/절대경로/domain/data/domain-construction-rental-v4;MODE=MySQL;AUTO_SERVER=TRUE
User       sa
Password   (없음)
```

**`AUTO_SERVER=TRUE` 를 꼭 붙인다.** 없으면 앱이 떠 있는 동안 `Database may be already in use` 가 난다.

`spring.h2.console.enabled=true` 가 켜져 있지만 **Spring Boot 4 에서는 동작하지 않는다** — 콘솔
자동설정이 빠져서 `/h2-console` 은 404 다. 대신 셋 중 하나를 쓴다.

**H2 자체 콘솔** (브라우저 UI)
```bash
java -cp ~/.gradle/caches/modules-2/files-2.1/com.h2database/h2/2.4.240/*/h2-2.4.240.jar \
  org.h2.tools.Console -web -webPort 8082
```
http://localhost:8082 에서 위 JDBC URL 을 입력한다.

**터미널**
```bash
java -cp .../h2-2.4.240.jar org.h2.tools.Shell \
  -url "jdbc:h2:file:$PWD/data/domain-construction-rental-v4;MODE=MySQL;AUTO_SERVER=TRUE" -user sa
```

**IntelliJ** Database 탭 → `+` → Data Source → H2 → 위 값 입력.

### 테이블

```
housing_complex     단지 × 공급유형          자연키 (hsmpSn, 공급유형명)
unit_type           주택형                  자연키 (단지, 이름, 전용, 주거공용)
notice              공고
notice_supply       공고 × 단지 × 주택형      카탈로그 FK 두 칸을 들고 있다
notice_schedule / reception_place / notice_attachment
```

## 5. 적재하면 이 정도가 나온다

`data/domain-construction-rental-v4`의 2026-08-16 21:52 KST 전체 재적재 기준이다.

```
단지     3,038   (고유 hsmpSn 2,837 × 공급유형)   시도 16개
주택형  10,024   전용면적·기본보증금 거의 100%
공고        52
공급행     273   단지 붙음 240 (88%) · 주택형 붙음 224 (82%)
```

**비어 있는 칸은 `unit_type.total_unit_count` 하나다** — 1,481 / 10,024 (15%). 이건 정상이고
이유가 둘이다. 원천인 15059475 가 국민·행복·영구 계열만 다뤄서 50년·10년·5년임대 1,933개는
구조적으로 0이고, 그 원천에 단지 ID·PNU·주소가 없어 LH식 단지명으로만 붙는데 마이홈 이름과
19%만 맞는다.

그리고 **LH 단지에만 찬다.** SH 709단지·기타 239단지는 0건이고, SH·GH 주택형별 세대수를 주는
원천은 포털에 없다(2026-08-16 재확인). `null` 이 정상값이고 `sum(total_unit_count)` 를 전국
물량으로 읽으면 안 된다.

공급행 주택형 미연결 49건도 정상 범위다. 면적·이름 모호는 0건이고 전부 앞 단계(주소·PNU·LH 원천) 손실이다.
자세한 건 [주택형-알갱이와-매칭.md](주택형-알갱이와-매칭.md) 에 있다.
