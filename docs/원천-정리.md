# 원천 정리 — 무엇을 이을 수 있고 무엇을 못 잇나

건설임대만 다룬다는 전제에서, 네 원천이 각각 **무슨 알갱이로 무슨 키를 주는지**, 그래서 **어디끼리 이어지고 어디서 끊기는지** 정리한다. 개별 필드 사전은 [원천-API-데이터-사전.md](원천-API-데이터-사전.md), 모델이 왜 그 모양인지는 [도메인-설계.md](도메인-설계.md)에 있다.

이 문서의 수치는 전부 적재된 실제 DB를 센 것이다(2026-08-13, 단지 2,969 · 공고버전 56 · 공급행 111).

---

## 1. 경계 — 건설임대만

| | 담나 | 왜 |
| --- | :---: | --- |
| 건설임대 | **○** | 공공이 지은 단지. 이름·주소·PNU·주택형이 다 있다 |
| 매입임대 | ✕ | 민간주택을 한 채씩 사들인 것. "단지"가 없고 단지명 칸에 지역명이 온다 |
| 전세임대 | ✕ | 세입자가 직접 구해온 집. 대상 주택이 우리 쪽에 없다 |
| 분양 | ✕ | 빌려주는 게 아니다. 보증금·계약금·잔금의 뜻도 다르다 |

허용 공급유형은 영구·국민·행복주택·통합공공·장기전세·5년·10년·50년임대 여덟이다. 이름으로 판정하지 않고 API별 코드 목록으로 거른다. 마이홈 공고는 요청 파라미터(`suplyTy`)부터 이 여덟만 돈다.

실적재 결과 전국 256개 시군구에서 단지 2,969개가 남고, 121,746건이 공급유형(매입·전세 등)으로, 248건이 "라벨은 건설임대인데 준공일·주택유형 증거가 없음"으로 걸러졌다.

## 2. 원천 넷 — 알갱이와 키

**알갱이(grain)**는 "원천 한 행이 무엇 하나인가"다. 이게 안 맞으면 조인이 성립하지 않는다.

| 원천 | 한 행이 무엇인가 | PNU | 주소 | 단지명 | 주택형 | 공급 세대수 |
| --- | --- | :---: | :---: | :---: | :---: | :---: |
| **15110581** 마이홈 단지정보 | 단지 × 공급유형 × 주택형 | ✅ | 도로명 | 마이홈식 | ✅ | 단지·유형 전체 |
| **15108420** 마이홈 모집공고 | 공고 × 공급행(단지) | ✅ | 전체주소 | 마이홈식 | ✕ | 공고 전체 |
| **15057999** LH 공고상세 `dsSbd` | 공고 × 단지 | ✕ | 지번 | **LH식** | 범위값만 | ✕ |
| **15056765** LH 공급정보 `dsList01` | 공고 × 단지 × **주택형** | ✕ | ✕ | **LH식** | ✅ | **이번 회차** |

여기서 두 가지가 갈린다.

**PNU는 마이홈 계열에만 있다.** 카탈로그와 공고 양쪽에 있고, 공급행 111건 전부가 PNU를 갖는다(누락 0). LH 계열(15057999, 15056765)에는 PNU도 `hsmpSn`도 없다.

**주택형별 공급 세대수는 15056765에만 있다.** 마이홈 공고는 "이 단지에 총 몇 호"까지고, LH 공고상세는 전용면적을 `36.67~51.93` 같은 범위 문자열로만 준다.

## 3. 단지명이 두 체계다 — 이 문서의 핵심

마이홈과 LH가 같은 단지를 **다른 이름**으로 부른다. 주소·세대수로 같은 단지임이 확인된 85쌍을 비교한 결과다.

```
이름 일치   16건 (19%)
이름 불일치 69건 (81%)
```

불일치의 실제 모습:

| 카탈로그(마이홈) | LH |
| --- | --- |
| `하나로아파트` | `군산조촌부향` |
| `김해구산주공1단지아파트` | `김해구산` |
| `4단지` | `화성동탄2 A24블록 영구임대` |
| `율계마을` | `고창율계 고령자복지(영구임대) 주택` |
| `산북부향하나로1차` | `군산부향1차` |
| `평화주공4단지` | `전주평화4 영구임대주택` |

마이홈은 **동네에서 부르는 이름**, LH는 **사업지구명 + 블록 + 공급유형**이다. 명명 체계 자체가 다르다.

**그래서 정규화로 못 고친다.** 공백을 지우고 괄호를 떼고 접미어를 잘라도 `하나로아파트`가 `군산조촌부향`이 되지 않는다. 유사도 임계값을 낮추면 틀린 단지가 붙기 시작한다 — 매입임대 단지명이 지역명이라 이름 매칭이 위험하다는 것과 같은 종류의 함정이다.

**LH 단지명을 카탈로그 단지명과 직접 대조하는 매칭은 성립하지 않는다.**

## 4. 그래서 무엇이 이어지나

측정된 링크만 적는다.

| 잇는 것 | 키 | 실측 |
| --- | --- | --- |
| 공고 공급행 → 카탈로그 단지 | **PNU** | 97 / 111 확정. 미매칭 8, 후보 다수 6 |
| 공고 공급행 → LH 공고상세 | **지번주소 접두어** | 95 확정(주소+세대수 46, 주소만 49). 미매칭 23, 세대수 충돌 3 |
| LH 공고상세 ↔ LH 공급정보 | LH식 단지명, 같은 공고 안 | **미검증** — 둘 다 LH 명명이라 맞을 가능성이 높지만 15056765를 아직 안 받았다 |
| LH 공급정보 → 카탈로그 단지 | 단지명 직접 대조 | **끊김 (19%)** |

그림으로 보면 이렇다.

```
[마이홈 계열] ───── PNU ─────┐
                            ↓
  공고 공급행 ──────────> 카탈로그 단지 ──> 주택형(전용면적)
      │
      └── 지번주소 ──> LH 공고상세 ─ ? ─ LH 공급정보(주택형·공급세대수)
                       (LH식 단지명)     (LH식 단지명)
```

`?` 구간만 아직 안 재 봤고, 나머지는 다 실측했다.

## 5. 주택형은 어떻게 얻나

여기가 이번에 다시 잡은 부분이다. **두 질문을 분리해야 한다.**

### 질문 A — "이 공고는 어느 주택형을 몇 호 공급하나"

**15056765를 적재하면 그 자체가 답이다. 매칭이 필요 없다.**

15056765 응답은 `PAN_ID`(공고)로 조회하고, 한 행이 `단지명 + 주택형 + 전용면적 + 이번 회차 공급 세대수`다. `PAN_ID`는 마이홈 공고의 `detail_url`에 이미 박혀 있어 새로 알아낼 값이 없다. 즉 **공고 → 주택형은 원천이 직접 준다.**

```
NoticeVersion ──1:1── LhUnitSupplyBatch ──< LhUnitSupply
                                             단지명 · 주택형 · 전용면적 · 공급세대수
```

이 경로에는 카탈로그도, PNU도, 이름 매칭도 안 들어간다. 원천 사실 그대로다.

### 질문 B — "그 주택형이 카탈로그의 어느 `UnitType`인가"

평면도·기준임대료 같은 카탈로그 정보를 붙이려면 필요하다. **이건 3단계 체인이고, 아직 안 풀렸다.**

```
LhUnitSupply ─ LH단지명 ─> LhComplexDetail ─ 주소 ─> 공급행 ─ PNU ─> 단지 ─ 전용면적 ─> UnitType
              (미검증)                    (95건)        (97건)
```

LH 단지명끼리 잇는 첫 구간이 관건이다. 같은 LH 시스템의 명명이라 3장의 19% 문제를 피해 갈 가능성이 높지만, 15056765를 실제로 받아 봐야 안다.

### 지금 코드의 상태

`NoticeHousingUnitTypeMatchService`는 질문 B를 풀려고 만들었는데, **첫 구간을 잘못 잡았다** — `LhUnitSupply`의 LH식 단지명을 `HousingComplex.name`(마이홈식)과 직접 비교한다. 3장에서 측정한 그 19% 조인이다. 지금 돌리면 대부분 `NO_SUPPLY_ROW`로 떨어진다.

`NoticeHousingCatalogMatch`(PNU 매칭)는 **없앨 수 없다.** LH 계열에는 PNU가 없어서, 공고를 카탈로그에 잇는 유일한 신뢰 가능한 키가 그것뿐이다. 다만 질문 A에는 안 쓰인다 — 질문 B의 마지막 구간에서만 쓰인다.

## 7. 남은 결정

1. **15056765의 단지명이 15057999의 단지명과 맞는가** — 질문 B 전체가 여기 달렸다. 15056765를 받아 보면 바로 답이 나온다.
2. **`SPL_INF_TP_CD`를 060/061/063에서도 검증** — 지금 실측한 건 062(국민임대) 한 건뿐이다. 적재된 공고의 공급유형 분포는 행복주택 21 · 영구임대 20 · 국민임대 13 · 50년 1 · 10년 1이라, 063(행복주택)이 다음 확인 대상이다.
3. **질문 B가 안 풀리면 어디까지 보여줄 것인가** — 질문 A만으로도 "59㎡ 20호 공급"은 보여줄 수 있다. 카탈로그 연결은 부가 기능으로 남겨도 된다.
